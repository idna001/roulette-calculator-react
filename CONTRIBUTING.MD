## Code of Conduct

This project and everyone participating in it is governed by the [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you are expected to uphold this code.

## How Can I Contribute?

### Reporting Bugs

If you find a bug, please ensure the bug was not already reported by searching on GitHub under [Issues](https://github.com/OWNER/REPOSITORY_NAME/issues). If you're unable to find an open issue addressing the problem, please [open a new one](https://github.com/OWNER/REPOSITORY_NAME/issues/new). Be sure to include a title and clear description, as much relevant information as possible, and a code sample or an executable test case demonstrating the expected behavior that is not occurring.

### Suggesting Enhancements

If you have an idea for an enhancement, please open an issue to discuss the feature. This allows us to coordinate efforts and prevent duplicated work.

### Your First Code Contribution

Unsure where to begin? You can start by looking through `good-first-issue` and `help-wanted` issues.

## Development Setup

1.  Fork the repository and clone it locally.
2.  **npm install** - Installs all dependencies required for the project.
3. **npm start** - Runs the app in development mode.
4.  **Open http://localhost:3000 in your browser to view the app.**
5.  Create a new branch for your changes: `git checkout -b name-of-your-feature-or-fix`

## Pull Request Process

1.  Ensure any install or build dependencies are removed before the end of the layer when doing a build.
2.  Update the `README.md` with details of changes to the interface, this includes new environment variables, exposed ports, useful file locations, and container parameters.
3.  You may merge the Pull Request in once you have the sign-off of at least one other developer, or if you do not have permission to do that, you may request the reviewer to merge it for you.

We use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) for our commit messages. This leads to more readable messages that are easy to follow. A good example is `feat: add user authentication endpoint`.
